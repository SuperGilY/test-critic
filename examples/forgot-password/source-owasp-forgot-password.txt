Introduction
- Forgot-password features are a common source of vulnerabilities, notably user enumeration.
- Quick-reference guidance: "Return a consistent message for both existent and non-existent accounts." Also keep response timing uniform, use a side channel to deliver the reset method, and prefer URL tokens for the simplest implementation.
- Tokens or codes should be cryptographically random, long enough, stored securely, single-use, and time-limited.
- Make no account changes (such as lockouts) until a valid token is presented.
- MFA reset is covered in a separate cheat sheet.

Forgot Password Service
- Request: Keep responses and timing consistent. Rate-limit per account or require a CAPTCHA to prevent flooding. Apply standard input validation and SQL injection defenses.
- User resets password: Verify identity via the token or code. Require the password to be entered twice and enforce the application's standard password policy. Store it securely and email a notice without the password. Don't log the user in automatically. Offer to invalidate existing sessions.
- Recovery after suspected compromise: Don't rely solely on recently changed recovery details. Don't automatically restore replaced contacts. Suspend compromised authenticators. Review recovery contacts and MFA methods with the verified owner. Invalidate sessions and outstanding reset links. Notify the user through all applicable channels, with instructions for reporting unauthorized recovery.

Methods
- General practices: Use a cryptographically secure RNG. JWTs are possible but add risk. Bind tokens to users, make them single-use, and store them securely.
- URL tokens: Email a token in the query string. Don't trust the Host header when building reset URLs; hard-code the URL or validate it against trusted domains. Use HTTPS. Set a no-referrer Referrer-Policy on the reset page. Rate-limit guessing. Set the new password.
- PINs: 6 to 12 digits, sent via SMS or similar. The user enters the PIN with their username, which creates a restricted session limited to resetting the password.
- Offline methods: Identifiers are stored offline (for example, in a password manager), and the backend still authenticates the request. Hardware OTP tokens and certificates are out of scope.
- Security questions: Never the sole reset mechanism; use only as an extra layer, with well-chosen questions.

Account Lockout
- Don't lock accounts in response to forgotten-password attacks, since this can deny access to legitimate users.
